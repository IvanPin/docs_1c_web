# Обработка сертификатов в 1С

[Контракт](../api/certificates.md) · [OpenAPI](../api/certificates-1c.openapi.json) · [Код](../api/certificates-code.md) · [Стенд](../../examples/certificates/README.md).

## Алгоритм

1. Регламентно читать `GET /api/1c/certificates/index.php?afterId=0&limit=50`. Продолжать по `nextAfterId` до `null`; каждый новый проход начинать с 0.
2. По ключу `site identity + orderId` найти существующий выпуск либо выпустить и активировать один сертификат на `amount` целых рублей, валюта `RUB`. DEV и production разделить. Исключить двойной выпуск параллельными обработчиками и обычным обменом заказов.
3. До первого callback транзакционно сохранить ключ операции, номер, постоянный `externalId`, сумму, валюту, срок и состояние подтверждения.
4. Отправить `POST /api/1c/certificates/index.php`: `orderId`, `number`, `externalId`, `amount`, `currency`, необязательное `expiresOn`.
5. Успех: HTTP 200, `status: 1`, исходный `result.orderId`, `result.accepted: true`. Сохранить подтверждение в 1С.
6. При timeout/500 повторять сохранённый POST из журнала, включая случаи, когда заявка исчезла из GET. Не перевыпускать сертификат. Интервалы опроса, таймауты и задержки повторов — настройки.
7. 400/413/422 — исправить запрос; 401/403 — доступ; 404/409 — ручной разбор. При конфликте не менять номер/ID автоматически. Ошибка одной заявки не блокирует остальные.
8. Журнал: сайт, orderId, время, HTTP/code, число попыток, состояние операции. API-ключ не логировать. Предусмотреть повтор после исправления и контроль зависших операций.

Письма отправляет сайт; ошибка почты не запускает новый выпуск.

## Проверки

| Сценарий | Результат |
|---|---|
| Оплаченная заявка | Один активный сертификат нужного номинала; сайт принял реквизиты |
| Повтор GET / параллельная обработка | Один выпуск на ключ |
| Повтор POST / потеря ответа | Повтор принят без перевыпуска |
| Перезапуск 1С после выпуска до POST | Отправлены ранее сохранённые реквизиты |
| Временная недоступность 1С | Заявка обработана в следующем проходе с 0 |
| Неверная сумма, подмена или занятый номер/ID | 409, операция направлена в разбор |
| Неоплаченный / отменённый заказ | Не выдан в GET; подтверждение отклонено |

## Параметры подключения

Согласовать окружение и ключ, идентичность сайта, номенклатуру и внешний код 1С, связь с обменом заказов, номиналы, активацию, срок и смысл отсутствующей даты, фискальные признаки, отмену после выпуска и отзыв. Метода отзыва в v1.0.0 нет.
