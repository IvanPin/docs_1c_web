# Сертификаты · API 1.0.0

[OpenAPI 3.1](certificates-1c.openapi.json) · [Алгоритм 1С](../tasks/certificates-1c.md) · [Код](certificates-code.md) · [Стенд](../../examples/certificates/README.md).

## Доступ

| Окружение | URL |
|---|---|
| DEV | `https://api.dev.plameneya.com` |
| Production | `https://api.plameneya.com` |

Подключение окружения и ключ предоставляются отдельно. HTTPS, заголовок `X-Api-Key`.

- GET: scope `certificates:read`.
- POST: scope `certificates:issue`.
- JWT и legacy-ключ без этих прав не подходят.
- Заголовок ответа: `X-Certificate-Contract-Version: 1.0.0`.
- `OPTIONS` без ключа: HTTP 204, `Allow: GET, POST, OPTIONS`.

## Получить очередь

`GET /api/1c/certificates/index.php?afterId=0&limit=50`

| Параметр | Тип | Правило |
|---|---|---|
| `afterId` | целое ≥ 0 | По умолчанию 0. Курсор внутри одного прохода |
| `limit` | целое 1–100 | По умолчанию 50 |

```json
{
  "status": 1,
  "code": null,
  "error": null,
  "result": {
    "items": [{
      "requestId": 1101,
      "orderId": 101,
      "amount": 5000,
      "currency": "RUB",
      "paid": true,
      "buyerName": "Тестовый покупатель",
      "buyerEmail": "buyer@example.invalid",
      "recipientName": "Тестовый получатель",
      "recipientEmail": "recipient@example.invalid"
    }],
    "nextAfterId": 1101
  }
}
```

Все ID и суммы — JSON-числа, не строки. `amount` — целые рубли. `requestId` используется для страниц, `orderId` — для идемпотентности выпуска и callback.

Передавать `nextAfterId` в `afterId` до `nextAfterId: null`. Каждый новый проход начинать с `afterId=0`. GET не удаляет заявки.

В очереди только оплаченные неотменённые заказы сертификата без подтверждённого выпуска. После принятого POST заявка исчезает. Неподтверждённая заявка повторяется в следующих циклах.

## Подтвердить выпуск

`POST /api/1c/certificates/index.php`, `Content-Type: application/json`

```json
{
  "orderId": 101,
  "number": "EXAMPLE-PL-000101",
  "externalId": "example-guid-from-1c",
  "amount": 5000,
  "currency": "RUB",
  "expiresOn": "2030-12-31"
}
```

| Поле | Обязательное | Тип и правило |
|---|---|---|
| `orderId` | Да | Положительное целое, ID заказа из GET |
| `number` | Да | Непустая строка до 128 символов, без управляющих символов; номер действующего сертификата |
| `externalId` | Да | Непустая строка до 128 символов; постоянный уникальный ID сертификата в 1С |
| `amount` | Да | Целое ≥ 1000, точно равно оплаченному номиналу |
| `currency` | Да | Строка `RUB` |
| `expiresOn` | Нет | Календарная дата `YYYY-MM-DD` или пустая строка; отсутствие равнозначно пустой строке |

Неизвестные поля отклоняются. Размер JSON — до 16 000 байт. Дата в примере условная; срок и правила отсутствующей даты согласуются отдельно.

```json
{"status":1,"code":null,"error":null,"result":{"orderId":101,"accepted":true}}
```

Идентичный повтор успешен, пока заказ оплачен и не отменён. Изменение номера, ID или срока, занятый номер/ID другого заказа, несовпадение суммы, отсутствие оплаты или отмена — 409.

## Ошибки и повторы

```json
{"status":0,"code":"CONFLICT","error":"Заказ не оплачен или отменён","result":null}
```

| HTTP | `code` | Действие 1С |
|---|---|---|
| 400 | `BAD_JSON` | Исправить синтаксис JSON |
| 401 | `UNAUTHORIZED` | Проверить ключ; не повторять бесконечно |
| 403 | `FORBIDDEN` | Проверить выданные права |
| 404 | `NOT_FOUND` | Сверить сайт и orderId; не выпускать новый номер |
| 405 | `METHOD_NOT_ALLOWED` | Использовать GET или POST |
| 409 | `CONFLICT` | Разобрать отмену, сумму или конфликт идентичности. Не менять номер автоматическим повтором |
| 413 | `PAYLOAD_TOO_LARGE` | Уменьшить тело запроса |
| 422 | `VALIDATION_ERROR` | Исправить типы/обязательные поля/дату/пагинацию |
| 500 | `INTERNAL_ERROR` | Повторить тот же запрос с задержкой |

При timeout или 500 повторять тот же сохранённый POST с задержкой. HTTP 200 подтверждает сохранение выпуска; письмо отправляется отдельно сайтом.

## Правила обработки

- Ключ выпуска в 1С: `site identity + orderId`; DEV и production разделены.
- Выпуск и активация — в 1С. Реквизиты сохраняются до первого POST, с защитой от параллельного выпуска.
- Неподтверждённый callback повторяется из журнала 1С, даже если заявка уже исчезла из GET.
- Письма отправляет сайт. Дизайн, пожелание и время вручения в обмен не входят.
- API остатка, списания, резервирования, восстановления и отзыва в v1.0.0 нет.
